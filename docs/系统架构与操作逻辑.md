# StylesVN 系统架构与操作逻辑

> 先说清楚一件事：**本工程是 Unity 2022.3 LTS（2022.3.62f3c1），不是 Unreal。**
> 如果你要的是 Unreal 版本的文档/迁移方案，那是另一件事，这份文档写的是「这套系统怎么运转、
> 玩家操作时状态怎么变」——即通常说的 UE（用户体验）与系统架构说明。
> 成品：`Builds/Windows/Styles.exe`、`Builds/Android/Styles.apk`。

---

## 一、总体架构

四层，单向依赖：**内容 → 解释器 → 表现层 → 子系统**。

```
Assets/StreamingAssets/content/*.json      内容层：章节 / 证据 / 人物 / 调查 / 询问 / 指认 / 原著对照
            │  ContentDatabase.Load()
            ▼
        ContentDatabase ──Flatten()──► List<Beat>（291 条演出指令，线性序列）
            │
            ▼
   GameDirector（解释器，纯逻辑）  ──IVnView 接口──►  GameUI（表现层，uGUI）
            │                                              │
            │ GameState（可变状态 + 存档）                    ├─ DialogueView  对话 / 选项 / 自动 / 快进 / 吐司
            ▼                                              ├─ Overlays      笔记本 / 档案 / 回顾 / 菜单 / 存读档 / 设置 / 知识卡 / 章节卡 / 结算
   SaveSystem / SettingsService                            └─ Puzzles       推理 / 现场调查 / 询问 / 最终指认
            ▲
            │
   AssetService（图）· AudioDirector（声）· FontService（字）
```

关键点：**解释器不碰任何控件**。它只按 `IVnView` 接口喊「该显示这句台词了」「该弹推理题了」，
界面层做完事回调 `next()` 让解释器继续。这样同一份剧本既能被真实界面驱动，也能被
自动通关自检里的假界面（`MockView`）驱动——**同一套内容，两个驱动器**，这是本项目可自动化验收的基础。

| 层 | 文件 | 职责 |
|---|---|---|
| 内容 | `Assets/StreamingAssets/content/*.json` | 章节 `chapters/ch*.json`、证据、人物、调查场景、询问对象、指认题、原著对照 |
| 解释器 | `Assets/Scripts/Core/GameDirector.cs` | 指令分发、条件分支（栈式 `if`）、跳转、状态推进、自动存档、`IVnView` 调用 |
| 状态 | `Assets/Scripts/Core/GameState.cs` | 章节进度、线索、旗标、已问话题、已查热点、指认记录、得分/失误、播放时长 |
| 表现 | `Assets/Scripts/UI/GameUI.cs` + `DialogueView` / `Overlays` / `Puzzles` / `UiFactory` | 纯代码构建的 uGUI 界面，无手工场景文件 |
| 子系统 | `Core/Services.cs`、`Core/SaveSystem.cs`、`Core/ContentSource.cs` | 资源加载与占位、音频、音量与画质、存档槽、设置持久化 |

### 启动链路

1. `Assets/Scenes/Boot.unity`（由 `Styles → 2. 生成启动场景` 生成）里只有三个组件：
   `AudioDirector`、`GameUI`、`SystemCheck`。
2. `GameUI.Awake` 建 Canvas（1920×1080 参考分辨率，`ScreenMatchMode` 取 0.5）+ 安全区适配，
   依次建背景层 / 立绘层 / 点击层 / 对话层 / 选项层 / 弹层 / HUD 层 / 吐司层。
3. 读 `StreamingAssets/content/index.json` → `ContentDatabase`，失败会在屏幕上吐司提示而不是崩。
4. 显示标题画面。**此时 HUD 是关掉的**（`SetVisibleGame(false)`），标题层最后创建所以画在最上面。

## 二、操作逻辑（玩家做的每个动作，系统里发生了什么）

### 1. 一层「透明点击层」负责推进剧情

全屏有一个几乎不可见的 `AdvanceLayer`（图片 alpha=0、`raycastTarget=true`）。
玩家点屏幕任意位置都由它接住并调用 `DialogueView.Advance()`：

- 正在打字 → 先把这一句显示完整（不跳句）；
- 已经显示完 → 触发 `_onAdvance`，解释器走到下一句。

对话框本体与姓名牌设了 `raycastTarget=false`，**否则点「→ 点击继续」的位置会被对话框挡住**（这是修过的一个 bug）。

HUD 的四个按钮（笔记本 / 人物 / 回顾 / 菜单）画在点击层之上，所以它们总是可点——这带来一条重要的边界：
**玩家可以在演出中途打开弹层、甚至直接返回标题**（见 §四）。

### 2. 键盘与辅助

| 输入 | 行为 |
|---|---|
| 空格 / 回车 | 等同点击推进 |
| Esc | 打开 / 关闭菜单（有弹层时优先给弹层） |
| 按住 Ctrl | 快进（松开即停） |
| 对话框上的「自动」 | 念完一句后等「设置 → 自动播放间隔」秒自动翻页；再点一次关闭 |
| 对话框上的「快进」 | 几乎立刻自动翻页；再点一次关闭 |

「自动 / 快进」与手点互不冲突：**玩家一点就接回手动**；对话框被收起（出选项、进推理 / 调查 / 询问）、
或玩家打开任何弹层时，自动翻页会停手——不会在玩家看笔记本的时候把剧情偷偷跑掉。

### 3. 解释器指令集

| 指令 | 作用 | 边界处理 |
|---|---|---|
| `chapter` | 章节卡（淡入 0.5s → 停 1.9s → 淡出 0.4s） | 卡片演出中途返回标题会被作废，不会再推剧情 |
| `say` | 一句台词（可挂 `fx` 特效与 `give` 发证据） | 空台词、超长台词：正文字号 20–30 自适应 + 溢出换行，不会被省略号截断 |
| `bg` / `bgm` / `sfx` | 换背景 / 音乐 / 音效 | 找不到素材：记一条警告并继续，不中断剧情 |
| `fx` | `flash` / `shake` / `fade` | 「减少动态效果」设置开启时降级 |
| `choice` | 选项（可带 `hint`、`give`、`goto`） | 空选项组不会卡死（假界面会记一条错误） |
| `deduce` | 推理题：答错计失误并扣 3 分，可重答，答对才出「继续」 | `answer` 越界会被自检拦下 |
| `investigate` | 现场调查：热点按百分比锚定，点满 `need` 个才出现「结束搜寻」 | 热点间距按**当前画布真实尺寸**松弛，任何画幅下可点区域都不重叠 |
| `ask` | 询问：问够 `need` 个话题才能结束；话题可被证据解锁 | 没解锁的话题点了只会提示，不消耗机会 |
| `note` | 知识卡（医学 / 法律 / 化学说明） | 只有「明白了」一个出口 |
| `accuse` | 最终指认：一个界面里连问 6 题，逐题记录「你的判断 / 事实 / 理由」 | 首题答错直接评 D；全对评 S |
| `ending` | 结算报告 + 自动存档 | 结算数字取自**真实游玩状态** |
| `label` / `jump` / `set` / `if` / `wait` | 标签、跳转、置旗标、条件分支、等待 | `if` 用栈实现嵌套；条件语法 `clue:x` / `notclue:x` / `flag:k>=n` / `;` 与 `&&` 连接 |

### 4. 存档与设置

- 存档槽：**3 个手动槽 + 1 个自动槽**（`SaveSystem.SlotCount = 4`，`AutoSlot = 0`），
  落在 `Application.persistentDataPath/saves/`。
- 自动存档时机：**每 8 条指令、或距上次超过 20 秒**，以及走到结局时。
- 存档内容：整个 `GameState`（章节、指令下标、线索、旗标、话题、热点、指认记录、得分、背景、时长）。
- 读档：从标题读档会自动创建解释器并收起标题（修过一个空引用 bug）；从菜单读档会先
  `EndCurrentFlow()` 收干净场面再装配状态。
- 设置：`settings.json`，含文字速度、自动播放间隔、BGM / 音效 / 语音音量、全屏、画质档位。
  **损坏的设置文件或存档不会崩**：解析失败回退默认值 / 返回 null 并提示。

## 四、边界逻辑：已经理清并锁住的几条

这些是本轮专门用自动化测试盯住的冲突点，每一条都对应一个自动化断言：

1. **演出中途返回标题**：HUD 永远在最上层，所以玩家能在调查 / 推理 / 选项 / 章节卡中途点「菜单 → 返回标题」。
   系统现在会做 `EndCurrentFlow()`：停掉解释器（含 `wait` 协程）、撤掉推理 / 调查 / 询问 / 指认面板、
   关掉选项层与章节卡、关掉自动翻页，并且**作废的章节卡不会再推剧情**（`Next()` 在 `Running=false` 时直接返回）。
2. **从标题读档**：此前解释器还不存在，点存档会空引用。现在读档入口会自动创建解释器、收起标题、
   并把对话框恢复出来。
3. **反复开新游戏**：`StartNewGame()` 会先清 `Running` 再跑，否则屏幕有界面但剧情永远不动；
   单例被销毁后会清空引用，避免拿到「假对象」后一路 MissingReferenceException。
4. **自动播放遇上弹层**：数据库层把「弹层开着」告诉对话层，自动翻页让路；出选项 / 进解谜时对话框收起，
   自动翻页自然停止。
5. **调查热点重叠**：热点按百分比锚定、间距必须按当前画布尺寸算——4:3 下画布横向会被压到 86%，
   在 1920×1080 参考尺寸下算出来的间距会让两个 96px 的方框叠住，被压住的那一角永远点不到。
6. **不同画幅**：16:9 / 20:9 / 4:3 各跑一遍全量自检（32 项）都必须全过。
7. **知识卡与关系图的「量像素」检查**：知识卡必须有正文（内容级断言）；
   关系图里每个头像必须画在自己的方框内、名字底衬不能互相叠也不能压到别人的头像。
   这两条对应的是「看一眼就知道不对、但从来没人量过」的问题。
8. **只问最低限度的询问会少拿证据**：3 场询问共 35 个话题、其中 16 个会发线索，而 `need` 只要求
   3+3+4 = 10 个。只问够最低要求结束 → 通关时 31/36 条证据；把话题问全 → 35/36。这是设计上的取舍，
   不是 bug，但**会直接改变结算屏上的证据数字**，测试时不要当成丢失。

## 五、参考的开源项目

做这套系统时对照过下面这些项目。它们都是**公开源码**的项目（许可以各自仓库为准，此处按仓库标注），
本工程没有直接拷贝它们的代码，只是参考了做法与惯例：

| 项目 | 许可 | 参考了什么 |
|---|---|---|
| [Ren'Py](https://github.com/renpy/renpy) | MIT | 视觉小说的**交互惯例**：say/choice/menu 三段式、存档槽（自动档 + 手动档）、自动前进（auto-forward）与快进（skip）、对话回顾（history）、quick menu。本作的「自动 / 快进 / 对话回顾 / 自动存档槽」基本照着这套惯例做，玩家上手不需要重新学。 |
| [Ink](https://github.com/inkle/ink)（inkle） | MIT | **叙事脚本的流程模型**：标签跳转 + 条件分支 + 变量状态，以及「把故事位置与变量一起序列化成一份状态」的存档思路。本作的 `Beat` 指令流 + `GameState`（章节 id + 指令下标 + 旗标 + 线索）与之同构。 |
| [Yarn Spinner](https://github.com/YarnSpinnerTool/YarnSpinner) | MIT | 对话节点 + 行内条件/指令的写法，以及**条件表达式必须人可读**的取向。本作条件语法 `clue:cup` / `flag:trust>=2` / `;` 与 `&&` 连接即由此而来。 |
| [Fungus](https://github.com/snozbot/fungus) | MIT | Unity 里做交互小说的**指令块 + 流程**做法。本作最终选了「一条线性指令数组 + 栈式 if」而不是可视化流程图，理由是纯代码更好做自动化验收（假界面可以完整驱动一遍剧本）。 |
| [Unity uGUI](https://github.com/Unity-Technologies/uGUI) | Unity Companion License（源码可读，非 OSI） | 全部界面控件的底座。因为本机的 Unity Package Manager 起步即崩，工程把 uGUI 源码内置到 `Assets/ThirdParty/uGUI`，界面全部用代码拼（`UiFactory`），不维护手工场景。 |
| TextMesh Pro（Unity 官方包） | 随 Unity 分发 | 中文排版、富文本（`<size>` / `<color>` / `<align>`）与打字机效果的 `maxVisibleCharacters`。 |
| [Noto Serif SC](https://fonts.google.com/noto)（Google） | SIL OFL 1.1 | 正文字体，工程内 `Assets/Fonts` + 由 `TmpFontBuilder` 生成中文 SDF 字体资产。 |
| [Newtonsoft.Json](https://github.com/JamesNK/Newtonsoft.Json) | MIT | 内容库与存档的 JSON 序列化（同样因为 UPM 不可用而内置 DLL）。 |
| [ComfyUI](https://github.com/comfyanonymous/ComfyUI) | GPL-3.0 | **仅作离线美术工具**（上一轮重做 27 张背景/立绘用的管线，见 `docs/美术管线_ComfyUI.md`）。它不与成品代码链接，成品里也不含它的任何代码，因此不受其 GPL 传染。 |
| [Monogatari](https://github.com/Monogatari/monogatari) | MIT | 网页版视觉小说引擎的**界面分层**参考（背景层 / 立绘层 / 对话框层 / 选项层 / 覆盖层），本作 Canvas 的层级顺序与之类似。 |

> 说明：引擎自身（Unity）与 TextMeshPro 不是开源项目，这里是「使用」而非「参考实现」；
> 表里标 OSI 许可的都是真开源项目。若后续要迁移到 Unreal，`ContentDatabase` 的 JSON 内容层与
> `GameState` 的存档模型可以直接沿用，需要重写的只有表现层。

## 六、自动化验收工具（已随成品交付）

成品自带一个体检开关，**不需要装编辑器、不需要连调试器**：

```bat
Builds\Windows\Styles.exe -styles-selfcheck -screen-fullscreen 0
```

它会（32 项）：

- 逐屏打开所有界面、**把每个按钮都真的点一遍**，检查版面是否跑出屏幕、按钮是否互相盖住；
- 单独测解释器的每一种指令、条件表达式、跳转分支、异常输入；
- 测存档写入 / 读回 / 损坏存档降级、设置写入 / 读回 / 损坏设置降级；
- 测「中途撤退」（调查 / 章节卡里返回标题）与「**真通关**」——用真实界面从标题一路玩到结算屏，
  并把界面里真实发生的次数与自动通关自检的期望值对照；
- 每一步截图，最后写 `ToolsOut/system_check.txt`（+ `.json` 与 `shots/` 截图目录）。

退出码 0 = 全过，1 = 有失败项，便于接到 CI 上。
