# 20 小时体量的制作计划

## 1. 先算清楚"20 小时"是多少内容

以中文视觉小说的实测阅读速度 **250 字/分钟** 计算（含点击、停顿）：

| 项目 | 数字 |
|---|---|
| 20 小时纯阅读 | **300,000 字** |
| 扣除调查/推理/询问等互动时间（约占三成） | **约 210,000~240,000 字正文** |
| 目前已完成的第一章（可运行垂直切片） | 11,031 字 ≈ **44 分钟** |
| 20 小时 ÷ 44 分钟 | **约 27 倍** |

也就是说：**20 小时不是"写长一点"，而是把现在这套结构复制并扩写 27 倍。**

## 2. 内容规模目标

按 8 幕、24 章规划（平均每章 50 分钟）：

| 类别 | 现状 | 20 小时目标 |
|---|---|---|
| 正文 | 11,031 字 | **220,000~250,000 字** |
| 演出指令（beat） | 289 条 | **5,800~6,500 条** |
| 章节 | 9 章（第一章内部） | **24 章 / 8 幕** |
| 现场调查场景 | 5 | **60~80** |
| 询问场景（话题数） | 27 | **400~500** |
| 推理题 | 8 | **120~150** |
| 证据条目 | 36 | **400~600** |
| 背景图 | 13（本次生成） | **150~200 张**（含昼夜/天气变体） |
| 角色立绘 | 10 位 × 1 表情 | **16~20 位 × 10~14 表情 ≈ 220~260 张** |
| CG 剧情插画 | 0 | **80~120 张** |
| 音乐 / 音效 / 语音 | 0 | BGM 30 首、音效 200 条、（可选）语音 8,000~15,000 句 |

## 3. 产能测算（基于本机实测）

| 环节 | 单位产能 | 20 小时所需工时 |
|---|---|---|
| 场景图生成 | 15~25 秒/张（4070 8G，SDXL+Lightning 8 步） | 200 张 × 3 版候选 ≈ **4 小时 GPU** |
| 立绘生成 | 20~30 秒/张 | 260 张 × 3 版 ≈ **6 小时 GPU** |
| CG 生成 | 30~45 秒/张（含放大） | 120 张 × 4 版 ≈ **5 小时 GPU** |
| 人工挑选 / 修图 / 抠图 | 2~4 分钟/张 | 约 **90 小时** |
| 剧本写作 | 8,000~12,000 字/天 | 230,000 字 ≈ **20~30 个工作日** |
| Unity 内容装配与调试 | 每章 1~1.5 天 | **24~36 个工作日** |
| 本地化（英/日）与校对 | 每万字 1.5 天 | **35 个工作日**（可外包） |

结论：**GPU 不是瓶颈，人和时间是瓶颈。** 生成 600 张图只需要十几个小时机器时间，
但挑选、修整、写词、装配才是 20 小时游戏的真实成本。

## 4. 排期（建议 5 个月，团队 4~6 人）

| 里程碑 | 周期 | 交付物 |
|---|---|---|
| **M0 垂直切片**（已完成） | — | Unity 工程 + PC 打包 + 安卓构建配置 + 剧本第一章 + ComfyUI 生产线 + 13 张背景 + 10 张立绘 |
| **M1 系统定稿** | 第 1~3 周 | 存档/设置/回顾/笔记本/推理/调查/询问全部打磨；商店页素材雏形；确定 5 张风格标杆图 |
| **M2 第一幕**（约 5 小时） | 第 4~9 周 | 6 章剧本、60 张背景、80 张立绘、20 张 CG、BGM 8 首；英文本地化同步 |
| **M3 第二幕 + 声音** | 第 10~15 周 | 再 6 章；CG 管线成熟；配音试录；安卓低端机性能达标（骁龙 6 系 / 4GB 内存 / 30fps） |
| **M4 第三、四幕** | 第 16~20 周 | 全部 24 章正文完成；400+ 证据；120 张 CG |
| **M5 打磨与发行** | 第 21~24 周 | 全平台打包（Steam / Windows / Android / iOS）、成就、云存档、商店页面、预告片、QA 回归 |

## 6. 移动端与 PC 的工程约定（已在代码内落实）

- **分辨率**：16:9 基准，`CanvasScaler` 自适应；背景用 `Envelope` 方式裁切，19.5:9 全面屏不露黑边；
  顶部导航区通过 `SafeAreaFitter` 避开刘海。
- **触控**：所有可点区域 ≥ 88px（参考分辨率），调查热点 96px，避免误触。
- **性能**：三档画质（低/中/高），低档 30fps、关闭抗锯齿与阴影；纹理上限 2048，安卓用 ASTC 6×6、
  PC 用 BC7；单章纹理内存目标 < 300MB。
- **包体**：正文放 `StreamingAssets`（当前 ~120KB，20 小时约 3~5MB，可接受）；
  美术资源在 M2 阶段迁移到 **Addressables** 并按章拆分，实现"下载即玩 + 按章加载"（APK 控制在 300MB 内，其余按需下载）。
- **存档**：`persistentDataPath/saves/slot0-3.json`，自动存档 + 3 手动槽，原子写入防损坏；字段带版本号，便于升级迁移。
- **输入**：鼠标 / 触屏统一走 uGUI；PC 支持空格推进、Ctrl 快进、Esc 菜单。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 美术风格漂移 | 20 小时后半段像换了个游戏 | IPAdapter 风格锚点 + M2 结束后训练风格 LoRA；美术总监统一挑选 |
| 文字量失控 | 排期崩塌 | 先定"每章 9,000 字 + 3 处互动"的硬指标；用 `tools/convert_from_js.js` 的统计脚本每周对表 |
| 8GB 显存限制 | 无法用 Flux 等更大模型 | 当前 SDXL 方案已足够；需要更高质量时可租云 GPU 批量跑同一套 `pipeline.py` |
| 本机 Unity UPM 进程崩溃 | 无法安装官方包 | 已把 uGUI / TMP / Newtonsoft 内置到 `Assets`，工程离线可用；详见 README 的说明 |
| 版权与商标 | 发行受阻 | 原著已公有领域；避免使用影视改编的形象与商标；字体与模型许可已核对 |

## 8. 每周对表用的三个数字

1. `ToolsOut/content_report.txt` 里的**正文字数**与**预计时长**；
2. `assets_manifest.json` 里**缺失素材数**（目标：每章归零）；
3. `ToolsOut/qa_report.json` 里**不合格图片比例**（目标：< 15%）。
